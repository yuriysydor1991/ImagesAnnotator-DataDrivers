## Customizing the installable library name segments

The library name that downstream consumers see (the library binary, the
`include/<name>/` subdir for public headers, the CMake package directory and the
imported-target namespace exported through `install(EXPORT ...)`) is derived
from three optional CMake options. They let parallel installs of distinct
versions of the library coexist on the same host - e.g.
`include/ImagesAnnotatorDataDrivers-0.11.0-dev/` next to
`include/ImagesAnnotatorDataDrivers-0.11/`.

| Option | Default | Effect |
|---|---|---|
| `-DLIB_INCLUDE_MINOR_IN_NAME=OFF` | `ON` | Drops the `.<minor>` the name carries by default |
| `-DLIB_INCLUDE_MICRO_IN_NAME=ON` | `OFF` | Appends `.<micro>` (implies the minor flag) |
| `-DLIB_NAME_SUFFIX=-dev` | `""` | Appends an arbitrary trailing tag |

Resulting library name examples for this `0.11.0` project:

| Configure flags | Library name |
|---|---|
| (none) | `ImagesAnnotatorDataDrivers-0.11` |
| `-DLIB_INCLUDE_MINOR_IN_NAME=OFF` | `ImagesAnnotatorDataDrivers-0` |
| `-DLIB_INCLUDE_MICRO_IN_NAME=ON` | `ImagesAnnotatorDataDrivers-0.11.0` |
| `-DLIB_NAME_SUFFIX=-dev` | `ImagesAnnotatorDataDrivers-0.11-dev` |
| `-DLIB_INCLUDE_MICRO_IN_NAME=ON -DLIB_NAME_SUFFIX=-dev` | `ImagesAnnotatorDataDrivers-0.11.0-dev` |

The default - `ImagesAnnotatorDataDrivers-0.11` - is the name every other
section of this documentation assumes. The minor version is part of it on
purpose: the public API namespace is `ImagesAnnotatorDataDrivers011`, carrying
the very same major and minor pair, so two minor versions install completely
side by side - distinct binaries, distinct header directories, distinct CMake
packages - and may even be linked into one and the same translation unit.

Change the name only if you deliberately want yet another side-by-side install,
and remember that whatever name you pick is the one your downstream
`find_package()` call has to spell.

Combined configure example:

```
# inside the project root directory

cmake -S . -B build \
  -DLIB_INCLUDE_MICRO_IN_NAME=ON \
  -DLIB_NAME_SUFFIX=-dev
cmake --build build
cmake --install build --prefix /usr/local
```

The same name is used consistently for every installed artefact. With the
defaults left alone and the `/usr/local` prefix that is:

- `/usr/local/lib/libImagesAnnotatorDataDrivers-0.11.so.0.11.0` (the shared library binary, plus the `libImagesAnnotatorDataDrivers-0.11.so.0` `SOVERSION` symlink and the `libImagesAnnotatorDataDrivers-0.11.so` linker name symlink),
- `/usr/local/include/ImagesAnnotatorDataDrivers-0.11/*.h` (the public headers install subdir, declared via the `INSTALL_INTERFACE` of the library target),
- `/usr/local/<libdir>/cmake/ImagesAnnotatorDataDrivers-0.11/` + the `ImagesAnnotatorDataDrivers-0.11::ImagesAnnotatorDataDrivers-0.11` imported target generated by `install(EXPORT ...)` - downstream CMake projects use `find_package(ImagesAnnotatorDataDrivers-0.11 REQUIRED)`. The `<libdir>` part is whatever `GNUInstallDirs` resolves `CMAKE_INSTALL_LIBDIR` to on your host (plain `lib` in the common case).

Note that the C++ namespace of the public API is a separate thing entirely and
is **not** affected by these options: it stays `ImagesAnnotatorDataDrivers011`,
with the major and minor version stamped into the identifier itself.

The derivation lives in [cmake/template-project-misc-variables-declare.cmake](/cmake/template-project-misc-variables-declare.cmake) and is exposed as the `PROJECT_LIBRARY_NAME` CMake cache entry that the rest of the build system consumes. Asking for `LIB_INCLUDE_MICRO_IN_NAME=ON` together with an explicit `LIB_INCLUDE_MINOR_IN_NAME=OFF` triggers a configure-time warning and the minor flag is turned back on implicitly, to keep the produced name syntactically valid.
