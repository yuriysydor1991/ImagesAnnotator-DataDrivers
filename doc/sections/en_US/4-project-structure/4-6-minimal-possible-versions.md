## Minimal possible versions

The project intentionally declares the lowest possible versions of the build tools and the language standard it relies on - the `cmake_minimum_required(VERSION 3.13)` requirement and the C++ `17` standard (`CMAKE_CXX_STANDARD` set to `17` with `CMAKE_CXX_STANDARD_REQUIRED` set to `ON`) of the root [CMakeLists.txt](/CMakeLists.txt). Keeping these requirements as low as practical lets the library be configured, built and installed across the widest possible range of environments, including older distributions and toolchains.

The C++17 standard is a real requirement and not a formality: the public [ImageRecord.h](/src/lib/facade/public/ImageRecord.h) header uses `std::filesystem` and the `inline` constants, so a consumer of the installed library is to be compiled with C++17 or newer as well - that is exactly what the example consumer of the [Using the library in your project](/doc/sections/en_US/8-using-the-library-in-your-project/8-using-the-library-in-your-project.md) section does.

This is a deliberate default and not a hard limit. You may, of course, raise any of the used versions whenever your target environment or your application needs it - bump the `cmake_minimum_required(...)` value, set a newer `CMAKE_CXX_STANDARD` (for example `20` or `23`), or require newer versions of any third-party dependency. Increasing a version only narrows the set of systems that are able to build the project, it does not change the project structure itself.
