## Налаштування ідентичності бази даних анотацій

Кожен файл проекту анотацій має корінь у вигляді елемента, названого іменем **застосунку**, якому належить формат, і несе під ним рядок версії:

```json
{
  "ImagesAnnotator": {
    "version": "0.14.0"
  },
  "annotations": [ ... ]
}
```

Ця пара - ім'я кореневого елемента і рядок версії - і є тим, що ця секція називає *ідентичністю бази даних*. Дві CMake cache-змінні задають її значення за замовчуванням часу компіляції, і обидві оголошені у [cmake/template-project-misc-variables-declare.cmake](/cmake/template-project-misc-variables-declare.cmake):

| CMake-змінна | За замовчуванням | Чим вона стає |
| --- | --- | --- |
| `ANNOTATIONS_DB_ROOT_APP_NAME` | `ImagesAnnotator` | ім'я кореневого елемента JSON у вироблених файлах, і те ім'я, за яким читач шукає кореневий елемент |
| `ANNOTATIONS_DB_APP_VERSION` | версія проекту, наразі `0.14.0` | рядок версії, що записується під тим кореневим елементом і порівнюється з тим, що знайдено у файлі, який читається |

Обидві передаються у згенерований `project-global-decls.h` через [src/project-global-decls.h.in](/src/project-global-decls.h.in), і обидві доступні для читання з програми-споживача через `IADataDriversFacade::default_db_root_app_name()` і `IADataDriversFacade::default_db_app_version()`.

### Чому значенням за замовчуванням є не ім'я бібліотеки

Це та частина, яку варто зрозуміти, перш ніж щось змінювати.

Бібліотека була виділена із застосунку [ImagesAnnotator](https://github.com/yuriysydor1991/ImagesAnnotator.git), а файли проектів, які той застосунок писав увесь цей час, мають корінь у вигляді елемента, названого буквально `"ImagesAnnotator"`. Кореневий елемент шукається **за іменем**: читач, який не знаходить очікуваного імені, відмовляється від документа.

Тож якби бібліотека штампувала там власне ім'я - `"ImagesAnnotatorDataDrivers"` - вона виробляла б файли, які той самий застосунок, заради якого вона й існує, більше не зміг би відкрити, і відмовлялася б відкривати файли, які той застосунок вже записав. Ось чому за замовчуванням береться ім'я *застосунку*, а не бібліотеки, і чому це налаштовуване значення, а не жорстко зашитий літерал.

Правило великого пальця: **не чіпайте обидві змінні**, якщо ви свідомо не рухаєте власний, інакше названий формат файлів. Зміна імені - це не косметична правка, це форк формату.

### Зміна під час конфігурації

Обидві є звичайними cache-змінними, тож вони йдуть у командний рядок `cmake`:

```
# всередині кореневої директорії проекту

cmake -S . -B build \
  -DANNOTATIONS_DB_ROOT_APP_NAME="MyTool" \
  -DANNOTATIONS_DB_APP_VERSION="2.0"
```

Кожен примірник бази даних, збудований таким бінарним файлом бібліотеки, після цього за замовчуванням матиме кореневий елемент `"MyTool"` і штамп версії `"2.0"`. Перевірити, що саме несе побудована бібліотека, можна не відкриваючи жодного файлу:

```cpp
#include <iostream>
#include <ImagesAnnotatorDataDrivers-0.14/IADataDriversFacade.h>

namespace iadd = ImagesAnnotatorDataDrivers014;

std::cout << iadd::IADataDriversFacade::library_version() << " writes '"
          << iadd::IADataDriversFacade::default_db_root_app_name() << "' rooted files, version "
          << iadd::IADataDriversFacade::default_db_app_version() << "\n";
```

Варто мати на увазі, що зміна часу компіляції запікається у спільну бібліотеку і тому впливає на **кожного** споживача того встановленого бінарного файлу. Дистрибутивний пакунок бібліотеки має постачати значення за замовчуванням. Якщо ж вам насправді потрібен один інакше проштампований файл із вашої власної програми - краще скористатися шляхом часу виконання, описаним нижче: він не потребує жодної перебудови і нікому не заважає.

Сама лише `ANNOTATIONS_DB_APP_VERSION` є значно менш небезпечною за ім'я: розбіжність між налаштованим значенням версії і тим, що знайдено у файлі, спричиняє лише попередження у журналі, і файл усе одно завантажується. Про цю поведінку - у секції [формат JSON проекту анотацій](/doc/sections/uk_UA/4-project-structure/4-10-the-annotations-project-json-format.md).

### Зміна під час виконання

Значення часу компіляції є лише значеннями за замовчуванням. Доступні два перевизначення часу виконання, і жодне з них не потребує перебудови бібліотеки.

**Через контекст бібліотеки**, перш ніж базу даних буде створено:

```cpp
auto ctx = iadd::IADataDriversFacade::create_library_context();

ctx->app_name = "MyTool";
ctx->app_version = "2.0";

auto db = iadd::IADataDriversFacade::create_annotations_db(ctx);

if (db == nullptr || !db->load_db("my-tool-project.json")) {
  return false;
}
```

Щойно створений контекст вже тримає у цих двох полях значення за замовчуванням часу компіляції, тож перезаписуйте лише те, що має бути іншим. Той самий контекст працює і з одноразовим шляхом `IADataDriversLib::libcall()`.

**Через саму базу даних**, у будь-який момент:

```cpp
auto db = iadd::IADataDriversFacade::create_annotations_db();

db->set_app_info("MyTool", "2.0");

std::cout << db->get_app_name() << " " << db->get_app_version() << "\n";
```

Обидва маршрути приводять в одне й те саме місце - `set_app_info()` є рівно тим, що варіант із контекстом викликає під капотом.

### Коли ідентичність береться до уваги

Час тут має значення, бо ідентичність читається на момент операції, а не зберігається разом із даними:

- **Під час завантаження** налаштоване ім'я є ключем, за яким шукається кореневий елемент, а налаштована версія - тим, з чим порівнюється версія з файлу. Тож `set_app_info()` має бути викликаний *до* `load_db()`, щоб мати хоч якийсь вплив на те завантаження.
- **Під час збереження** налаштовані ім'я і версія записуються такими, якими вони є в ту саму мить. Нічого з того, що ніс раніше завантажений файл, не запам'ятовується.

Другий пункт має практичний наслідок: завантаження файлу зі штампом `0.10.0` і його зворотне збереження зі значеннями за замовчуванням виробляє файл зі штампом `0.14.0`. Коли збереження початкового штампу має значення, вичитайте його і поставте на місце перед збереженням:

```cpp
auto db = iadd::IADataDriversFacade::open_annotations_db("project.json");

if (db == nullptr) {
  return false;
}

// зберігаємо ту ідентичність, з якою налаштовано цей екземпляр, але не
// піднімаємо мовчки версію файлу, записаного старішим застосунком
db->set_app_info(db->get_app_name(), db->get_app_version());
```

І дзеркальне відображення цього: щоб перетворити файл з однієї ідентичності застосунку на іншу, завантажте його під старим іменем і збережіть під новим.

```cpp
auto ctx = iadd::IADataDriversFacade::create_library_context();

ctx->app_name = "ImagesAnnotator";  // ідентичність, яку несе вхідний файл

auto db = iadd::IADataDriversFacade::create_annotations_db(ctx);

if (db == nullptr || !db->load_db("input.json")) {
  return false;
}

db->set_app_info("MyTool", "2.0");  // ідентичність, яку має нести вихід

return db->store_db("output.json");
```
