### Ручний запуск тестів

На даний момент усі тести розділені в окремі файли які мають шаблонну назву `UTEST_*` (для юніт тестів) і `CTEST_*` (для компонентних тестів).

Можна виконати пошук усіх збудованих тестів наступною командою:

```
# всередині кореневої або директорії побудови

find -type f -executable -name 'UTEST_*' -o -type f -executable -name 'CTEST_*'
```

Після чого необхідно обрати шлях до бажаного тесту і запустити його виконання за потреби. Наприклад, для запуску юніт тесту класу `LibraryFacade` необхідно передати його відносний шлях від кореневої директорії (в даному випадку) у командний рядок (для GNU/Linux ОС і подібних):

```
# з кореневої директорії

./build/src/lib/facade/tests/unit/LibraryFacade/UTEST_LibraryFacade
```

Компонентний тест бази даних директорії анотацій запускається точнісінько так само. На відміну від юніт-тестів він лінкує справжню побудовану динамічну бібліотеку і працює з нею виключно через встановлювані публічні заголовкові файли, отож те, що він перевіряє, є тим самим шляхом виконання коду, яким пройшов би проект-споживач бібліотеки:

```
# з кореневої директорії

./build/src/dbs/AnnotationsDBs/tests/component/AnnotationsDirDB/CTEST_AnnotationsDirDB
```

Кожен з цих бінарних файлів є звичайним виконуваним файлом GoogleTest, отож `--gtest_list_tests` показує, що всередині нього, а `--gtest_filter=<шаблон>` виконує підмножину:

```
# з кореневої директорії

./build/src/records/tests/unit/ImageRecord/UTEST_ImageRecord --gtest_list_tests
./build/src/records/tests/unit/ImageRecord/UTEST_ImageRecord --gtest_filter='*full_path*'
```
