### Запуск тестів за допомогою ctest

Якщо розробник увімкнув цілі побудови тестів за допомогою змінних `ENABLE_UNIT_TESTS` і/або `ENABLE_COMPONENT_TESTS` і після успішної їх побудови, можна пустити на виконання усі наявні тести з допомогою команди `ctest` з директорії побудови проекту (для GNU/Linux ОС і подібних):

```
# з директорії побудови проекту

ctest
```

Додай прапорець `--output-on-failure`, щоб одразу отримати вивід GoogleTest тих випадків, які не пройшли, замість голого переліку назв:

```
# з директорії побудови проекту

ctest --output-on-failure
```

Як альтернатива, можна виконати команду `ctest` з будь-якого розміщення у файловій системі за допомогою абсолютного шляху до директорії побудови проекту (для GNU/Linux ОС і подібних):

```
ctest --tests-dir /шлях/до/директорії/побудови/проекту
```

Для того щоб виконати окремий конкретний тест необхідно виконати команду `ctest` з назвою теста вказаного після прапорця `-R`. Наприклад, для юніт тесту `UTEST_IADataDriversFacade` команда буде виглядати на щось подібне:

```
# всередині директорії побудови проекту

ctest -R UTEST_IADataDriversFacade
```

Прапорець `-R` приймає регулярний вираз, який зіставляється із зареєстрованою назвою випадку, а випадки тут реєструються у вигляді `<назва бінарного файлу>.<випадок>.<аргументи>`, отож той самий прапорець звужує пошук настільки, наскільки забажаєш - до цілого бінарного файлу або до одного окремого випадку:

```
# кожен компонентний тест бази даних директорії анотацій
ctest -R CTEST_AnnotationsDirDB

# один конкретний випадок
ctest -R UTEST_DefaultDBMerger.appends_new_records_and_skips_duplicates
```

Використовуй `ctest -N` щоб переглянути перелік зареєстрованого, нічого не запускаючи.

Скрипт [debug-test.sh](/scripts/build/debug-test.sh) із секції [Швидкі скрипти побудови](/doc/sections/uk_UA/5-project-build/5-37-quick-build-scripts.md) виконує той самий виклик `ctest` всередині директорії `build/debug` - як самостійно, так і кроком скриптів побудови `Debug`, - щоразу, коли надано параметр `--test` (для GNU/Linux ОС і подібних):

```
# в середині кореневої директорії проекту

scripts/build/debug-test.sh --test
```
