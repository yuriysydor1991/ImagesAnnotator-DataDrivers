### Запуск бінарних файлів тестів і програми, злінкованої з бібліотекою

Динамічна бібліотека не є тим, що запускають - вона є тим, що завантажує інша програма. Отож тут можна запускати рівно дві речі: бінарні файли тестів, які будує даний проект, і твою власну програму, злінковану з бібліотекою.

#### Безпосередній запуск бінарного файлу теста

Якщо тести було увімкнено на стадії конфігурації і вони успішно скомпілювались, запусти будь-який з них у терміналі за шляхом, знайденим у попередньому підрозділі:

```
# з директорії побудови
./src/lib/facade/tests/unit/LibraryFacade/UTEST_LibraryFacade
```

Це звичайні виконувані файли GoogleTest, отож усі звичні прапорці працюють: `--gtest_list_tests` щоб побачити, що всередині, і `--gtest_filter=...` щоб виконати підмножину:

```
# з директорії побудови
./src/lib/libmain/dbs/AnnotationsDBs/tests/unit/mergers/DefaultDBMerger/UTEST_DefaultDBMerger --gtest_list_tests
```

Однак запуск їх по одному є здебільшого зручністю для налагодження - для запуску усього набору за один раз використовуй натомість команду `ctest`, див. підрозділ [Запуск тестів за допомогою ctest](/doc/sections/uk_UA/6-run-the-executable/6-3-1-run-tests-by-the-ctest.md).

#### Запуск програми, злінкованої з бібліотекою

Після встановлення бібліотеки (див. секцію [Встановлення](/doc/sections/uk_UA/7-installing/7-installing.md)) твоя власна програма підхоплює її через `find_package()` і запускається як і будь-який інший виконуваний файл:

```
# з директорії побудови твого власного проекту
./mytool /шлях/до/файлу/проекту-анотацій.json
```

Дві речі зазвичай ідуть не так з першої спроби, і обидві стосуються динамічного завантажувача, а не даного проекту:

- `error while loading shared libraries: libImagesAnnotatorDataDrivers-0.so.0` означає, що завантажувач не заглядає у директорію, у яку було встановлено бібліотеку. Або онови кеш завантажувача командою `sudo ldconfig` після встановлення у системний префікс, або вкажи завантажувачу на власний префікс для одного запуску:

```
LD_LIBRARY_PATH=/usr/local/lib ./mytool /шлях/до/файлу/проекту-анотацій.json
```

- встановлення у нетиповий префікс має також бути знаходжуваним під час конфігурації твого власного проекту, для чого і призначена змінна `CMAKE_PREFIX_PATH`:

```
cmake -S . -B build -DCMAKE_PREFIX_PATH=/твій/префікс/встановлення
```

Щодо повного опрацьованого прикладу такої програми - `CMakeLists.txt`, `main.cpp` і виклики API у ньому - див. секцію [Використання бібліотеки у власному проекті](/doc/sections/uk_UA/8-using-the-library-in-your-project/8-using-the-library-in-your-project.md).
